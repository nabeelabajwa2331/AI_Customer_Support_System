# Deployment: Render (API + database) and Vercel (frontend)

```
Browser ──► Vercel (React app) ──HTTPS──► Render (Express API) ──► Render PostgreSQL + pgvector
                                                │
                                                ├──► Groq API   (chat: llama-3.1-8b-instant)
                                                └──► Gemini API (embeddings: 768 dimensions)
```

Locally nothing changes: the defaults still use Ollama (`CHAT_PROVIDER=ollama`).

## 0. Before you start

- Push the latest code to GitHub (`git push origin main`).
- Accounts (all have free tiers, sign up with GitHub/Google):
  - Render — https://render.com
  - Vercel — https://vercel.com
  - Groq — https://console.groq.com → **API Keys → Create** (starts with `gsk_`)
  - Google AI Studio — https://aistudio.google.com/apikey → **Create API key** (starts with `AIza`)
- Keep the two keys somewhere safe. Paste them **only** into the Render dashboard, never into
  code, chat, or Git.

## 1. Backend on Render

1. Render dashboard → **New → Blueprint** → choose the `AI_Customer_Support_System` repository.
   Render reads `render.yaml` and proposes:
   - `support-desk-api` (web service, `server/` folder)
   - `support-desk-db` (PostgreSQL 16)
2. Fill in the values it asks for:
   | Key | Value |
   |---|---|
   | `CHAT_API_KEY` | your Groq key |
   | `EMBEDDING_API_KEY` | your Gemini key |
   | `CORS_ORIGINS` | leave a placeholder like `https://example.com` for now (set in step 3) |
   | `GOOGLE_CLIENT_ID` | leave empty for now |
3. Click **Apply**. The first build takes ~3–5 minutes. Migrations run automatically on start
   (they also enable the `vector` extension).
4. Check `https://<your-api>.onrender.com/api/health` returns `{"success":true,...}`.
   Copy the API address, e.g. `https://support-desk-api.onrender.com`.

`AUTH_SECRET` is generated by Render automatically — you never see or type it.

## 2. Frontend on Vercel

1. Vercel dashboard → **Add New → Project** → import the same repository.
2. **Root Directory:** `client` (click *Edit* next to it). Framework is detected as **Vite**.
3. **Environment Variables:**
   | Key | Value |
   |---|---|
   | `VITE_API_BASE_URL` | `https://<your-api>.onrender.com/api` |
4. **Deploy.** Copy the site address, e.g. `https://support-desk.vercel.app`.

## 3. Connect them

1. Render → `support-desk-api` → **Environment** → set `CORS_ORIGINS` to the Vercel address
   (no trailing slash). Several are allowed, comma-separated. Save — Render redeploys.
2. Open the Vercel site → **Create an account** → ask a question. (Until a document is uploaded,
   the assistant correctly says it has nothing to answer from.)

## 4. Create your admin account

Render's free plan has no shell, so run the existing script **from your own computer** against the
Render database:

1. Render → `support-desk-db` → **Connect** → copy the **External Database URL**.
2. In PowerShell, in the `server` folder:
   ```powershell
   $env:DATABASE_URL = "<paste External Database URL>"
   npm run create-admin
   ```
   It asks for name, email and a password (typed hidden). Close the terminal afterwards so the
   database URL is not kept in that session.
3. Sign in on the Vercel site with that account and upload your policy documents in
   **Knowledge Base** (they are embedded with Gemini).

## 5. Google sign-in (optional)

1. Google Cloud Console → **APIs & Services → Credentials → Create credentials → OAuth client ID
   → Web application**.
2. **Authorized JavaScript origins:** your Vercel address (and `http://localhost:5173` for local).
   No redirect URI is needed.
3. Render → `support-desk-api` → **Environment** → `GOOGLE_CLIENT_ID` = the client ID
   (`….apps.googleusercontent.com`). The client **secret** is not used — do not enter it anywhere.
4. The "Continue with Google" button appears automatically after Render redeploys.

## Things to know

- **Free web service sleeps** after ~15 minutes without traffic; the next request takes
  ~30–60 seconds while it wakes. Upgrade the service plan to avoid this.
- **Free Render PostgreSQL expires** 30 days after creation (Render emails before). For a longer
  free database, create one on Neon (https://neon.tech, pgvector supported) and set its URL as
  `DATABASE_URL` instead of the Render database.
- **Rate limits:** chat 10 questions/minute/user, uploads 20/hour/user
  (`CHAT_RATE_LIMIT_PER_MINUTE`, `UPLOAD_RATE_LIMIT_PER_HOUR`). Groq's free tier also has its own
  per-minute limits.
- **Data:** customer questions and retrieved document passages are sent to Groq and Gemini.
- **Embedding model changes** create a different vector space. If you ever change
  `EMBEDDING_API_MODEL`, delete and re-upload documents so old and new vectors are not mixed.

## Troubleshooting

| Symptom | Fix |
|---|---|
| Frontend says "Cannot reach the server" | Check `VITE_API_BASE_URL` (must end in `/api`) and redeploy Vercel; wait for Render to wake |
| Browser console shows a CORS error | `CORS_ORIGINS` must exactly match the Vercel address, no trailing slash |
| Render deploy fails at start with `Invalid environment configuration` | The log names the missing variable (usually an API key) |
| Upload fails with "embedding model is unavailable" | Check `EMBEDDING_API_KEY` |
| Chat returns "The AI model is unavailable right now" | Check `CHAT_API_KEY`, or Groq rate limits |
